# Lonora architecture

Lonora is a private, single-owner gold market operator. This repository is a fork of OpenClaw. OpenClaw remains the runtime. Boty is a capability source, not a second product.

## Map

| OpenClaw subsystem                                                        | Decision                                                              |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Gateway, sessions, streaming, retries, cancellation, recovery             | KEEP                                                                  |
| Cron / automations scheduler                                              | KEEP. Owner nav calls it Tasks                                        |
| Memory core                                                               | KEEP as conversation memory. Trading memory lives in the Lonora store |
| Plugin SDK, tool registration, approvals                                  | KEEP                                                                  |
| Provider runtime, including Anthropic, OpenAI, Z.AI, OpenRouter           | KEEP                                                                  |
| Telegram channel                                                          | KEEP. Other channels stay installed and are hidden                    |
| Usage and cost accounting                                                 | KEEP and ADAPT. No customer billing                                   |
| Control UI shell                                                          | ADAPT to the Lonora workspace                                         |
| Coding tools, terminal, browser, nodes, git                               | KEEP BUT HIDE. Blocked from the model by the Lonora tool policy       |
| Plugin marketplace, extra channels, meetings, dashboards, apps            | KEEP BUT HIDE from the owner navigation                               |
| CLI, tests, Doctor, migrations                                            | KEEP as developer infrastructure                                      |
| Public registration, orgs, billing, credits                               | REMOVE from the owner experience. No second account path is added     |
| Boty custom gateway, scheduler, and sub-agent framework                   | REMOVE. Not ported                                                    |
| Boty gold detectors, sessions, recommendation grading, execution boundary | REPLACE the missing domain                                            |
| Boty activation rules                                                     | REPLACE. A stored rule gates the fill; a close is not a wick touch    |

## Dependency risks

- The default OpenClaw tool profile stays `full` so existing runtime tests keep their contract. Lonora narrows the model with `before_prompt_build` and blocks coding tools in `before_tool_call`.
- Settings and sidebar lists are pinned by UI tests. Those tests were updated with the owner navigation.
- The Lonora SQLite file is opened by the plugin service. Gateway database rules prefer a worker. This store is plugin-owned state, not the Gateway database.
- Live candles require `OANDA_API_TOKEN`. Without it the market page reports unavailable data and does not invent a price. The chart draws only closed candles that are already visible at the current time. A swing range is classified from those closes: a wick does not complete it, a short sample stays unclassified, and no measured-move target is stored. A double top or double bottom is named when two swings sit within 0.4 ATR of each other and a later close clears the neckline. A triple top or triple bottom is named when three swings sit within 0.5 ATR and a later close clears the farther of the two pullbacks. A three-touch level is not renamed as a double. That height is not saved as a target. A rectangle is two flat highs and two flat lows, at least 1.2 ATR tall and 12 bars wide. A later close beyond either side completes it. A close through the other side after that fails the breakout. The height is not a target. A support or resistance line is kept only while closes stay inside 0.25 ATR of it. A wick may pierce it. Two opposite swings on a parallel line, between 1 and 8 ATR away, name a channel. Neither line is saved as a target. The last closed price is placed in the recent high-low range as premium, discount, mid-range, or near an edge. Fewer than twenty closed candles leave that location unread. A buy in premium or a sell in discount is still that direction, and the note says the location does not favor an immediate entry. The prior gold day runs from 18:00 New York to the 17:00 halt. Its high and low come from an earlier day with at least four closed hours, and the forming day is left out. Those two prices are structural levels when they sit beyond the last close. A sample with only the current day leaves the prior day unread. The market page and the model prompt name Sydney, Tokyo, London, and New York from each center's own clock. An overlap is named only when both are inside those hours. A weekend gap names the next center and how long until it opens. That clock does not replace the coarse UTC bucket used for case fingerprints, and it does not describe how price will move. A head and shoulders is named when the head clears both shoulders by 1.2 ATR and the shoulders stay within a quarter of the head height. An ascending triangle is a flat ceiling and a rising floor, and a descending triangle is the reverse. A symmetrical triangle or a wedge must converge. A later close beyond the expected boundary completes the shape. A close through the other side, or an apex mostly consumed without a break, fails it. The height is not saved as a target. A flag is an impulse followed by a shallow pause, and a pennant is that pause narrowing. A cup is a rounded base with a handle that stays in the upper half. A later close beyond the pause or the rim completes it. The impulse and the cup depth are not saved as targets. The latest closed candle can be named (a hammer after a decline, a hanging man after a rise, an engulfing body). The name is not a trade and stores no target. The recommendations page reads the same realized XAUUSD record as memory. Below five completed wins and losses it states the count and does not state a win rate.
- `lonora_execute_trade` never calls a broker. The tool hook ignores model-supplied confirmation. The manual path returns `not_linked` until a real adapter is intentionally added.

## One owner

The Lonora store holds one owner row. A Boty migration with more than one user fails until `--owner` is explicit, and a dry run writes nothing. An automatic local placeholder with no recommendations or memories can be replaced by that explicit owner. Imported plans keep a real created time so historical candles are not graded as if the plan started at epoch. A readable `activation_rule_json` is kept and gates later grading. An unreadable rule is imported as blocked, so it cannot fill on a touch. Gold limit entries and targets use a 10–15 point band and record the price the candle actually traded. A retest entry fills only when a candle trades inside its stored band, at a price that candle printed. A missing band, or a band that reaches the stop, does not fill. Stops stay exact. A gold scenario block is rebuilt from closed recommendations and replaces the previous block. Fewer than five completed outcomes produces no win rate and no stored block. A new recommendation prepared from closed candles places the stop beyond a tradable supply or demand zone by the volatility buffer, and only when a structural target already clears the distance floor. When gold is closed, that plan is a scenario for the next New York open: a market entry becomes a limit that waits, and the note names the close. It does not invent a live price or send an order. A zone graded below B is not saved. Extra targets are later structural levels, never an ATR projection. A pending path is not a trade back toward the zone. A zone that price has already broken is not saved. A missing spread is named as unread, and a higher timeframe built from too few closed bars stays unread. Neither is filled in as a tight spread or an aligned trend. Web and Telegram turns prepend the same gold-memory brief from the Lonora store. A material monitor notice is stored as the single latest market observation in that brief. An unchanged check, or a closed market with nothing material, does not write one and does not invent a price. A memory-curator note is compacted to 240 characters and stored as a lesson in that brief. A blank note stores nothing, and a refused delegation stores nothing. An empty store says nothing is stored and does not invent a rate. OpenClaw conversation search remains a separate store. Closed candles can be indexed into earlier moments whose outcomes use only later bars. Fewer than eight resolved similar moments produce a count and no rate. The market page and the research specialist read that comparison. Model-supplied candles are not the sample. It does not place an order. Web, Telegram binding, tasks, memory, and settings use that row.

## Monitoring

The service timer is not an LLM loop. One pass runs at a time. Each pass reads the gold clock, fetches closed candles only when the market is open and OANDA is configured, then runs deterministic structure and liquidity-sweep checks. It also reads the economic calendar. A failed or disabled feed stays unknown and does not become a quiet week. A high-impact gold-relevant event inside two hours is material, including while gold is closed. A gold headline is material only after the headline feed succeeds. A missing key, a disabled feed, or a failed read stays unknown and is not described as a quiet tape. An empty successful read is a quiet window. A new sweep is material. A closed market does not announce a price move. A sweep without a structure change runs the liquidity analyst; a structure change still runs the structure analyst. A specialist run is recorded only after a material change, and only inside the optional daily budget. A responsibility's last event is the owner-language notice for what matched. The reason code stays on the decision. Usage rows take the provider and model from the model event. An unpriced usage event fails that budget closed. Failed notices wait before the next attempt. A monitor exception is stored as a failed data status. Direct session spawn is blocked. Specialist bursts are capped from recent recorded runs, and the model cannot set its own depth. The system guardian reports that live count, and it reports the trade and coding blocks only after reading them. A call without those readings says the check did not run.

A material notice is sent through the gateway message tool to the bound Telegram chat. The message uses the owner language and the calendar or headline summary already read for that pass. The monitor keeps its reason code on the decision, and that code is not the text the owner receives. If Telegram is unbound or the send fails, the notice stays failed with a recorded reason. A morning or daily briefing is registered as a weekday 08:00 America/New_York cron turn when the host scheduler accepts it. Other responsibilities stay on the monitor and record whether the latest check matched the instruction, is still waiting, or is waiting because gold is closed. A scheduled briefing is not rewritten as "still waiting" on every monitor pass.

## Sequence already started

1. Audit and this map.
2. Lonora plugin: owner, tools, recommendations, memory, specialists, migration.
3. Owner navigation, four providers, Telegram-only channel list, trading welcome prompts.
4. Market and recommendation pages bound to gateway methods.
5. Tasks, Agents, and Usage & Cost read Lonora responsibilities, specialists, and cost rollups. Settings opens a four-provider connection page. An accepted key is saved with `models.authSetApiKey`. A rejected key is not. The older automations, agent, usage, and model-provider screens stay registered for direct links.
6. Tests, docs, and upstream notes.
